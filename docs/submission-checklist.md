# PortalPulse 参赛提交清单

截至 2026-10-09，项目仅处准备阶段，以下事项均为未来交付检查项，未代表已经实现、部署、发布或提交。依据：[本届官方 V3 Hacker House 详情](https://dorahacks.io/hackathon/portaldot-hacker-house-2026/detail)，本轮已读取该页的时间、提交及代码要求；赛道为[Node Operations & Tooling](https://dorahacks.io/hackathon/portaldot-hacker-house-2026/tracks)。2026 年 4 月 Mini Hackathon 模板不作为本届 V3 提交规则。

## Check-in：2026-10-24 20:00 前（北京时间）

- [ ] 如实说明当前进度和未完成事项。
- [ ] 提供公众可访问的 GitHub 仓库，完整 README、持续更新的开发记录和产品架构图。
- [ ] 提供 Portaldot 测试网部署信息：真实网络身份、适用的合约地址、交易哈希和可用时的浏览器链接；原始主网只读结果不能替代这些材料。
- [ ] 提供可演示的原型或核心流程；选择可运行网页 / Web3 DApp 链接，或最多三分钟、展示至少一个核心功能的视频。
- [ ] 若原型使用模拟数据，明确标示。官方允许 Check-in 演示材料使用模拟数据，并鼓励真实测试网交互；PortalPulse 自身验收仍要求完整真实测试网流程。
- [ ] 在 DoraHacks 提交后回读材料、链接与提交状态，留存结果。

官方 Check-in 不接受仅停留于概念设计的项目，因此当前准备仓库本身尚不满足该阶段交付。[Check-in 规则](https://dorahacks.io/hackathon/portaldot-hacker-house-2026/detail)。

## 最终提交：2026-11-06 12:00 前（北京时间）

- [ ] 项目名称、团队成员和一句话简介完整且真实。
- [ ] GitHub 仓库公开可访问，含完整 README、部署说明、项目文档和可复现 / 可运行的最终代码。
- [ ] README 提供真实安装与运行命令、环境及锁定依赖版本、部署和使用说明；披露框架、官方 SDK 及第三方来源与许可。
- [ ] 架构图与交付功能、代码和部署保持一致。
- [ ] 提供可运行演示：网页 / DApp 链接，或 README 中清楚的本地部署说明；在新环境实测复现。
- [ ] 提供真实 Portaldot V3 测试网部署信息，及适用的合约地址、交易哈希、区块哈希、执行结果、最终确认与状态读回证据；浏览器可用时提供相应链接。
- [ ] 演示视频**最多三分钟**，链接公开可访问，展示真实产品、核心功能和 Portaldot 集成 / 使用。
- [ ] Pitch Deck 为 PDF 或公开可访问链接，说明解决的问题、为何需要 Portaldot、产品功能实证及继续支持的理由。
- [ ] 按[十项产品验收](acceptance.md)留存实际验证；发布材料与源码包逐项回读，无私钥、助记词、认证信息或无关内部资料。
- [ ] DoraHacks 最终提交后回读字段、链接与成功状态；保存提交时间和版本，进入代码冻结。

区块、执行、最终确认和状态读回记录是 PortalPulse 的产品证据要求；官方最终提交明确要求适用的合约地址和交易哈希。产品证据与官方字段要求应分别核对，不能凭演示点击或文件存在认定提交成功。[最终材料规则](https://dorahacks.io/hackathon/portaldot-hacker-house-2026/detail)。
