# PortalPulse 未来验收标准

状态日期：2026-10-09。以下是实施完成后必须逐项验证的标准，**全部尚未执行，不能视为通过的测试**。当前只读主网观测仅见[网络预检](network-preflight.md)，不满足探针或产品验收。标准对应[设计](design.md)的六个模块。

## 采样和状态的精确标准

- 默认每 **10 秒**采集一次；每个请求 **8 秒**超时。
- 始终显示观察窗口、采集开始/结束时间和最后更新时间；离线导入显示原始来源与采集时间，不能标成实时在线。
- 至少观察**三个相邻区块变化**才建立间隔基线；之前区块推进为未验证，不能显示正常。
- 建立基线后，超过 **max(180 秒, 3 倍区块间隔中位数)** 未观察到推进时报警。连接失败、数据陈旧、没有区块推进分别展示，最终确认推进独立展示。
- 本地上限为 **2,000 条观测**；超过时删除最早记录，并提示保留窗口范围。不能将这段观测或条数作为全天可用性。
- 正常、异常、未验证、采集中四类状态各有明确依据；超时、元数据缺失、无法解码和查不到记录都不能转成成功。
- 连接错误可重连；写入不能自动重签或重复发送。已知主网创世哈希必须拒绝写入；身份或测试网能力不明时禁用写入。
- 导出带结构版本并检查 SHA-256；摘要只检测改动，不提供单一 RPC 之外的独立共识证明。
- 探针只存发起者自己的测试序号；更新其他发起者状态、资金转移或私钥托管均不属于首版功能。

实施时将为这些场景补充实际测试与交付证据。当前没有源码测试、部署回执、实时 UI 或可运行演示；也没有声称现有材料达到 Check-in 或最终提交要求。活动材料要求见[提交清单](submission-checklist.md)，依据[本届官方详情](https://dorahacks.io/hackathon/portaldot-hacker-house-2026/detail)。
